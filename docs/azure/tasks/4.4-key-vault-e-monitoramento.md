## `infra/keyvault.bicep`, trecho a trecho

- **Nome:** `'kv-${take(namePrefix, 9)}-${take(uniqueString(resourceGroup().id), 8)}'` dá 21 caracteres. O padrão dos outros módulos (`kv-payment-webhooks-<13>`) daria 33, e o limite do Key Vault é 24.
- **`enableRbacAuthorization: true`:** permissões por role assignment, como no resto do projeto, em vez de access policies.
- **`enableSoftDelete: true`, 90 dias:** não dá para desligar em cofres novos; a propriedade só deixa isso explícito.
- **Sem `enablePurgeProtection`:** ligar é irreversível e impediria apagar o cofre por 90 dias.
- **Role assignment:** `Key Vault Secrets User` (`4633458b-17de-408a-b874-0445c86b69e6`) para a identidade da API, com escopo no cofre. O nome é um `guid(vault.id, nome da identidade, role)`, o mesmo padrão da 4.2, para o `what-if` conseguir analisá-lo. O worker e o migrator não recebem nada: não leem segredos.
- **Outputs:** só o nome e a URI do cofre.

## `infra/monitoring.bicep`, trecho a trecho

- **`workspaceCapping.dailyQuotaGb: json('0.2')`:** o teto da seção 9. Bicep não aceita decimal literal, então usa `json('0.2')`, como o `minCapacity` do SQL.
- **`retentionInDays: 30`:** o padrão, incluído na ingestão.
- **Application Insights com `WorkspaceResourceId`:** modo baseado em workspace; os dados ficam no workspace e é lá que o teto vale.
- **Sem connection string nos outputs:** output de template aparece no histórico de deploys. A 4.5 e a 5.6 decidem como a aplicação a recebe.
- **Sem alertas:** a arquitetura os lista em `monitoring.bicep`, mas a tarefa 5.7 os cria.

## Comandos rodados

Providers que a assinatura ainda não tinha registrado (mesmo problema da 4.2):

```powershell
az provider register -n Microsoft.KeyVault --wait   # idem OperationalInsights e Insights
# Microsoft.KeyVault Registered / Microsoft.OperationalInsights Registered / Microsoft.Insights Registered
```

Build e `what-if` (só criações novas: Application Insights, cofre, role assignment, workspace):

```powershell
az bicep build --file infra/main.bicep --stdout > $null   # exit 0
az deployment group what-if -g rg-payment-webhooks -p infra/main.bicepparam
```

Deploy:

```powershell
az deployment group create -g rg-payment-webhooks -n task-4-4 -p infra/main.bicepparam
# state: Succeeded
```

Papel do desenvolvedor e segredos (a chave de 32 bytes aleatórios é gerada na hora e vai direto ao cofre, sem aparecer no terminal):

```powershell
az role assignment create --assignee-object-id <seu object id> --assignee-principal-type User --role "Key Vault Secrets Officer" --scope <id do cofre>
az keyvault secret set --vault-name kv-payment-w-gvi3ltqy -n admin-api-key --value <chave gerada>
az keyvault secret set --vault-name kv-payment-w-gvi3ltqy -n stripe-webhook-secret --value "pending-task-4.9"
```

`stripe-webhook-secret` guarda um marcador: a referência da 4.5 precisa de um segredo existente, e a 4.9 grava o valor real (uma versão nova). Até lá o webhook responde `400`.

Para ler a chave de administração (quando precisar do botão de reprocessar):

```powershell
az keyvault secret show --vault-name kv-payment-w-gvi3ltqy -n admin-api-key --query value -o tsv
```

## O que deu errado e como foi resolvido

- **Providers não registrados:** `Microsoft.KeyVault`, `Microsoft.OperationalInsights` e `Microsoft.Insights` estavam `NotRegistered`. Conferidos antes do deploy e registrados à mão.
- **`az monitor app-insights component show`:** pede a extensão `application-insights` e falha sem terminal interativo. Troquei por `az resource show --resource-type Microsoft.Insights/components`, que não precisa de extensão.
- **`az role assignment create --query roleDefinitionName` não imprimiu nada:** a concessão existia, confirmada com `az role assignment list` no cofre. Conferir sempre por leitura, nunca pela saída do `create`.

## Armadilhas que ficam

- Apagar o grupo deixa o cofre em soft delete e reserva o nome por 90 dias; recriar o ambiente com o mesmo nome falha com `VaultAlreadyExists` até `az keyvault purge --name kv-payment-w-gvi3ltqy` (e `az keyvault list-deleted` mostra quem segura o nome).
- O papel Secrets Officer do desenvolvedor foi concedido à mão e se perde se o grupo for recriado.
- Nada envia telemetria ainda: o workspace e o Application Insights existem, mas o exportador chega na 5.6.
