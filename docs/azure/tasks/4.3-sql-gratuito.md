# Tarefa 4.3: banco SQL gratuito

Serviços explicados em [azure-sql.md](../azure-sql.md) e [managed-identity-rbac.md](../managed-identity-rbac.md). Arquitetura: seções 8 e 10. Este documento descreve o que está no repositório (`infra/`), não o plano.

## O que foi criado

| Recurso | Detalhe | Arquivo |
| --- | --- | --- |
| Servidor SQL | Admin Entra ID, autenticação por senha desligada, TLS 1.2 | `infra/sql.bicep` |
| Banco `Payments` | Oferta gratuita, serverless, `AutoPause` ao esgotar | `infra/sql.bicep` |
| Regra de firewall | `AllowAllWindowsAzureIps` (0.0.0.0) | `infra/sql.bicep` |
| 3 usuários contidos | Um por identidade, com os papéis da seção 8 | `infra/sql/create-users.sql` |

O admin vem das variáveis de ambiente `SQL_ADMIN_LOGIN` e `SQL_ADMIN_OBJECT_ID`, lidas por `infra/main.bicepparam` (o login é o e-mail do desenvolvedor, por isso não fica no arquivo versionado).

## O Bicep, trecho a trecho

```bicep
administrators: {
  administratorType: 'ActiveDirectory'
  principalType: 'User'
  login: adminLogin
  sid: adminObjectId
  azureADOnlyAuthentication: true
}
```

`azureADOnlyAuthentication: true` remove a senha do servidor: não existe `sa` na nuvem. O administrador é uma pessoa (você), não uma identidade de aplicação.

```bicep
sku: { name: 'GP_S_Gen5', tier: 'GeneralPurpose', family: 'Gen5', capacity: 2 }
properties: {
  useFreeLimit: true
  freeLimitExhaustionBehavior: 'AutoPause'
  autoPauseDelay: 60
  minCapacity: json('0.5')
  maxSizeBytes: 34359738368
  requestedBackupStorageRedundancy: 'Local'
}
```

- `useFreeLimit` liga a oferta gratuita (100.000 vCore-segundos e 32 GB por mês).
- `AutoPause` é o que garante que o "pronto quando" da tarefa não vire cobrança: ao esgotar, o banco pausa até o mês seguinte.
- `maxSizeBytes` = 32 GB (34.359.738.368 bytes), o teto da oferta.
- Backup `Local`, a opção mais barata.

A regra `0.0.0.0` libera só serviços do Azure (para o Container Apps conectar). Quem entra de fato é decidido pelo login Entra ID e pelos usuários contidos. O IP do desenvolvedor entra à mão com `az sql server firewall-rule create`, porque é pessoal e muda.

## O script de usuários

`infra/sql/create-users.ps1`:

1. Lê o `clientId` de cada identidade com `az identity show`.
2. Converte o GUID em bytes (`([guid] $clientId).ToByteArray()`) e monta `0x...`. É a representação de SID que o SQL espera.
3. Chama o go-sqlcmd com `ActiveDirectoryAzCli` (usa o seu `az login`) e passa os três SIDs como variáveis.

`infra/sql/create-users.sql` cria cada usuário só se não existir (`IF NOT EXISTS`, então pode rodar de novo) e dá os papéis:

| Identidade | Papéis no banco |
| --- | --- |
| api | `db_datareader` |
| worker | `db_datareader`, `db_datawriter` |
| migrator | `db_datareader`, `db_datawriter`, `db_ddladmin` |

Por que `WITH SID ..., TYPE = E` e não `FROM EXTERNAL PROVIDER`: ver [azure-sql.md](../azure-sql.md), seção 5. A seção 8 da arquitetura foi reescrita nesta tarefa por esse motivo.

## Como foi verificado

O "pronto quando" pedia conexão sem senha com `az login` e a opção de pausar ao esgotar a quota ligada.

```bash
az sql db show -g rg-payment-webhooks -s <servidor> -n Payments --query "{free:useFreeLimit,exhaust:freeLimitExhaustionBehavior}"
# free: true, exhaust: AutoPause
az sql server show ... --query "administrators.azureADOnlyAuthentication"   # true
sqlcmd -S <servidor>.database.windows.net -d Payments --authentication-method ActiveDirectoryAzCli -Q "SELECT USER_NAME()"
# devolveu o usuário Entra
# consulta de sys.database_role_members: cada usuário com seus papéis
# o script rodou uma segunda vez sem erro
```

## O que deu errado

- **`RegionDoesNotAllowProvisioning` em East US 2 e East US.** A assinatura só cria servidores em regiões que a API `Microsoft.Sql/locations/<região>/capabilities` marca como `Available`. O grupo foi apagado e recriado em Central US, e a seção 10 foi atualizada.
- **Papéis do Service Bus sumiram após recriar o grupo.** O primeiro deploy disse `Created`, mas minutos depois as 5 atribuições não existiam; um segundo deploy as recriou. Provável causa: a limpeza assíncrona do grupo antigo removeu as novas. Registrado em `docs/pending.md` para a 4.8.
- **Falta provar o login de cada identidade.** O que foi provado é o usuário e os papéis no banco; nenhuma identidade conectou ainda. Fica para a 4.6.

## Decisões

| Decisão | Por quê |
| --- | --- |
| `AutoPause` em vez de cobrar excedente | O custo nunca passa do orçamento |
| Admin por pessoa, variáveis de ambiente | O login é um e-mail; não vai para o repositório |
| Script versionado em `infra/sql/` | Único passo manual fora do Bicep (exceção à NFR7); a pipeline não tem acesso ao plano de dados do banco |
