# Tarefa 4.2: identidades e Service Bus

Serviços explicados em [managed-identity-rbac.md](../managed-identity-rbac.md) e [service-bus.md](../service-bus.md). Arquitetura: seções 6, 8 e 10. Este documento descreve o que está no repositório (`infra/`), não o plano.

## O que foi criado

| Recurso | Nome | Arquivo |
| --- | --- | --- |
| 3 identidades user-assigned | `id-payment-webhooks-api`, `-worker`, `-migrator` | `infra/identity.bicep` |
| Namespace Service Bus Basic | `sb-<prefixo>-<hash>` | `infra/servicebus.bicep` |
| Fila `payment-events` | lock 60 s, 5 entregas, TTL 14 dias, dead-letter ao expirar | `infra/servicebus.bicep` |
| Fila `payment-notifications` | lock 60 s, 5 entregas, TTL 1 min, sem dead-letter ao expirar | `infra/servicebus.bicep` |
| 5 atribuições de papel, uma por par fila/identidade | ver tabela abaixo | `infra/servicebus.bicep` |

`infra/main.bicep` orquestra os módulos e passa os `principalId` das identidades para o módulo do Service Bus.

## O Bicep, trecho a trecho

**Identidades.** Três recursos `Microsoft.ManagedIdentity/userAssignedIdentities`, com nome vindo do `main.bicep` (`id-${namePrefix}-api` etc.). O módulo devolve o `principalId` de cada uma como saída, porque é ele que o RBAC pede.

**Namespace.**

```bicep
sku: { name: 'Basic', tier: 'Basic' }
properties: { disableLocalAuth: true }
```

`Basic` evita a taxa fixa do Standard. `disableLocalAuth: true` desliga as chaves SAS: depois disso só Entra ID entra, então não existe segredo para vazar. O nome usa `uniqueString(resourceGroup().id)` porque o nome do namespace é único no mundo.

**Filas.** Os valores vêm da tabela da seção 6. A diferença que importa é `deadLetteringOnMessageExpiration`: `true` em `payment-events` (evento expirado precisa ficar guardado) e `false` em `payment-notifications` (aviso expirado é lixo por desenho).

**Papéis.** Os dois papéis são identificados por GUID fixo do Azure (`69a216fc-...` Data Sender, `4f6d3b9b-...` Data Receiver). Cada atribuição tem `scope` na fila, não no namespace:

| Identidade | Fila | Papel |
| --- | --- | --- |
| api | `payment-events` | Data Sender |
| api | `payment-events` | Data Receiver (ler e reprocessar a dead-letter) |
| api | `payment-notifications` | Data Receiver |
| worker | `payment-events` | Data Receiver |
| worker | `payment-notifications` | Data Sender |

O nome de cada atribuição é `guid(fila.id, nomeDaIdentidade, papel)`. Usei o **nome** da identidade, não o `principalId`, porque o `principalId` só existe depois do deploy e o `what-if` não consegue calcular o nome do recurso com ele.

## Como foi verificado

O "pronto quando" pedia: `what-if` limpo e o deploy criando namespace e filas, com dead-letter ao expirar só em `payment-events`.

```bash
az bicep build --file infra/main.bicep                                  # exit 0
az deployment group what-if -g rg-payment-webhooks -p infra/main.bicepparam   # 6 creates + 5 role assignments
az deployment group create -g rg-payment-webhooks -p infra/main.bicepparam -n task-4-2   # Succeeded
az servicebus queue show ... -n payment-events         # deadLetteringOnMessageExpiration: true
az servicebus queue show ... -n payment-notifications  # deadLetteringOnMessageExpiration: false
az role assignment list --scope <cada fila>            # igual à tabela acima
```

## O que deu errado

- **GUID do papel Data Receiver errado no plano.** Foi corrigido com `az role definition list`. Lição: nunca copiar GUID de memória.
- **Provedores não registrados.** `Microsoft.ServiceBus` e `Microsoft.ManagedIdentity` não estavam registrados na assinatura nova; registrei à mão com `az provider register`.
- **`what-if` ainda mostra 7 modificações depois do deploy.** São ruído: defaults do serviço nas filas que o Bicep não declara, e referências a `principalId` que ele não resolve. Os valores reais batem. Está em `docs/pending.md`.

## Decisões

| Decisão | Por quê |
| --- | --- |
| Grupo de recursos e orçamento ficam fora do Bicep | A pipeline só terá Contributor no grupo; criar o grupo exige escopo de assinatura (seção 10) |
| Papel por fila, não por namespace | Menor privilégio: o worker não pode enviar para `payment-events` |
| `disableLocalAuth: true` desde o começo | Evita que uma chave SAS seja usada por conveniência e nunca removida |
